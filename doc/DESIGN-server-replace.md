# 설계 메모 — 「서버 판으로 교체」: 내 폴더를 서버 정본으로 맞추는 동사

> 오너 문제 제기: 원격 소스를 다른 사람이 업데이트했다. 나도 과거에 한 작업이 있어 로컬본이
> 있다. 그러면 내 로컬본을 밀고 원격의 것으로 치환하는 옵션이 있어야 할 것 같다.

**상태: 구현 완료 · 미발행.** 설계 = Fable · 이름·잔재 알림 수위 = 오너 · 구현 = Opus · 3축 = Fable(조건부 → §12 이행).

---

## 0. 결론 요약

**정책 한 줄**: 「작업 폴더」 묶음에 새 명령 하나(`zalkera.site.updateFromServer` · 라벨
**「서버 판으로 교체」**)를 더한다. 정본 tar 를 **받은 뒤에만** 폴더를 비우고, 성공하면
**표식을 받은 판으로 다시 쓴다.** 잔재(`.zalkera-stash-*`) **감지·안내**를 같은 판에 싣는다
(자동 삭제·자동 복원은 안 싣는다).

| 항목 | 판정 | 요지 |
|---|---|---|
| 한 동사로 묶기 | **채택** | 편의가 아니라 **정확성** 문제다 — 두 걸음 경로는 표식을 못 갱신해 다음 발행마다 거짓 409 동의가 뜬다(§2) |
| 잔재 회수 | **같은 판** | 입구를 늘리는 판이 노출 인구를 늘린다. 감지·안내까지. **자동 삭제·자동 복원 기각** |
| 내 작업 소실 | **권함(강제 안 함)** | 확인 모달에 「zip 으로 내보내기 먼저」 **둘째 단추**. 더티 검출 기각 |
| 어느 판 | **`pickRevision` 재사용**(활성 우선 · 없으면 최신 READY) | 판 고르는 판정을 두 벌 만들지 않는다 |
| 표식 | **성공 시 `FetchedMark` 로 덮어쓴다** — core 합성 함수 «안»에서 | 실패 시 옛 표식 보존 → 소속은 안 잃는다 |
| 자리 | **「작업 폴더」 묶음만** | 사이트 전환 화면 다섯째 선택지는 **기각**(§3) |
| 이름 | **「서버 판으로 교체」** | 오너 결정. 「교체」가 파괴성을 싣는다 |

⚠ **이름이 「어느 판인지」를 안 담는다.** 활성 판 우선이라는 사실은 **툴팁과 확인 모달이 판
번호로** 말해야 한다 — 이름에서 덜어 낸 부담이 문면으로 옮겨 간 것이다.

## 1. 현 상태 (코드 사실)

- **두 걸음으로는 오늘도 된다**: 「소스 zip 다운로드」 → 「zip 으로 교체」.
- **받기는 비어 있지 않은 폴더를 거절한다** — `fetchSource.ts` 「받을 폴더가 비어 있지 않습니다」.
  재현: `grep -n "받을 폴더가 비어 있지 않습니다" packages/core/src/fetchSource.ts`
- **파괴적 교체 기계의 입구는 하나뿐이다** — `replaceContents` 호출부가 `updateZipCommand` 한 곳.
  재현: `grep -rn "replaceContents(" packages/*/src --include="*.ts" | grep -v "\.test\.ts"`
- **잔재를 아는 코드 0건** — `.zalkera-stash-` 를 만드는 자리와 그 시험, 배송 문서 둘뿐.
  재현: `grep -rln "zalkera-stash" packages scripts doc`
  ⚠ **이 구멍은 `DEFERRED.md` 에 미등재였다** — 배송 문서의 정직 고지에만 있었다.
- **zip 출처 표시는 판 번호를 모른다** — `Provenance` 는 `{format, claim, tenant}` 뿐.
  재현: `grep -n "revisionNo" packages/core/src/provenance.ts` → 0건
- **zip 은 표식을 안 싣는다** — `EXCLUDED_PATHS` 에 `.zalkera/source.json`.
- **「zip 으로 교체」는 옛 표식을 되살린다** — `replaceContents(dir, [SOURCE_MARK_PATH], keep, …)`.

## 2. 왜 한 동사인가 — 두 걸음은 «결과가» 틀린다

판 N 에서 받은 폴더를 zip 두 걸음으로 판 M 에 맞추면, zip 은 `.zalkera` 를 못 싣고
「zip 으로 교체」는 옛 표식을 보존하므로 **표식이 여전히 N 을 선언한다.** 다음 발행은 기반 N 을
선언하고 서버에는 M 이 있으므로 **매번 「남이 올린 판이 있습니다」 동의 모달**이 뜬다 — 자기
손으로 방금 받아 온 그 판을 두고.

**거짓 경보를 습관으로 누르게 훈련시키면 진짜 경보도 눌러 버린다.**

한 동사는 판 번호와 sha 를 아는 자리에서 교체하므로 표식을 옳게 다시 쓸 수 있다 — **두 걸음
조합으로는 원리상 불가능하다**(zip 문은 판 번호를 모른다). 부수 이익: 낱장 zip 이 디스크에 안
남고(내보낸 소스 사본 = 유출면), 대화상자 왕복이 준다.

⚠ 이 절은 **코드 추적**이다. 상용 왕복 실측은 아니다.

## 3. 기각한 대안

| 안 | 기각 사유 |
|---|---|
| 두 걸음의 기계적 연결(자동 체인) | 풀기→싸기→다시 풀기 3회에, **zip 문을 지나는 순간 판 번호를 잃어** §2 결함이 그대로다. 임시 zip 도 남는다 |
| 받기의 「비어 있지 않음」 거절을 「덮을까요?」로 완화 | 그 거절은 이 도구 최대 손해(고치던 소스를 조용히 밀기)를 막는 **정본 가드**다. 받기 문에 파괴 갈래를 접붙이면 「내려받기 셋은 있는 파일을 덮지 않는다」는 약속이 깨진다 — 파괴 동사는 파괴 묶음에 따로 선다 |
| 사이트 전환(elsewhere) 화면의 다섯째 선택지 | elsewhere 는 **정의상 소속≠고른 사이트**다. 거기의 「이 폴더를 교체」는 소속 변경+파괴를 한 클릭에 묶는다 — 「소속을 바꾸는 동사는 사이트에 연결 하나」 위반. 게다가 오너 시나리오는 **같은 사이트** 안이라 그 화면을 안 지난다 |
| 임의 판으로 교체(판 선택 UI) | 받기 문 셋이 전부 `pickRevision` 하나를 쓴다. 새 문만 판을 고르면 판정이 두 벌. 판 축은 「버전 전환」·「버전 이력」이 담당 |
| 더티 검출로 모달 분기 | 표식 sha 로 폴더 내용을 대조하는 것은 `localMark.ts` 가 명시적으로 금지한 형상이다(「폴더는 판 N 과 달라야 정상」) |
| 교체 전 자동 백업 zip | 제스처 없는 쓰기 증가 + 교체마다 소스 사본이 조용히 쌓인다. 탈출구는 **보이는 단추**로 준다 |

## 4. 형상 설계

**core / 확장 경계** — 표식 계약 전체를 core 에 내린다. 확장 배선에 두면 시험이 못 문다.

```ts
// packages/core/src/fetchSource.ts (형제들 옆)
export interface RefreshSourceResult extends FetchSourceResult {
    preserved: string[]; kept: string[];
    /** 표식을 다시 썼는가 — 못 썼으면 옛 표식이 그대로 있고 그 사유. */
    mark: {written: true} | {written: false; reason: string};
}
export async function refreshSiteSource(options: {
    api: ZalkeraApi; revisionNo: number; targetDir: string; tenant: string;
    keep: readonly string[];   // 확장이 keepNames(dir) 로 잰다 — zip 문과 «같은» 술어
    onProgress?: (m: string) => void; fetchImpl?: typeof fetch;
}): Promise<RefreshSourceResult>;
```

**내부 순서(상태 전이)**

1. `fetchVerifiedSourceTar` — **네트워크 먼저, 파괴는 나중.** 전송·sha 대조가 끝나기 전에는
   폴더에 손대지 않는다. 파괴 창이 「내려받기+해제」에서 **해제만**으로 준다.
2. `replaceContents(targetDir, [SOURCE_MARK_PATH], keep, fill)` — 기존 기계 그대로.
   `fill` = `extractTarGz(buffer, dir, {rejectVendored, maxBytes})` — **형제 `fetchSiteSource` 와
   똑같이** 푼다(§11 R1).
3. 성공 시 표식: 보존한 옛 표식을 읽고 `decideImportBinding` 을 지나 `bind` 면
   `writeSourceMarkTo(root, {tenant, revisionNo, sha256, fetchedAt})` 로 **덮어쓴다.**
   `keep`(남의 사이트 표식)·`unknown` 이면 안 쓴다. 쓰기 실패는 **던지지 않고** `mark.reason` 으로 —
   옛 표식이 남아 소속은 안 잃고, 다음 발행이 동의를 한 번 더 받는 강하로 끝난다.

**확장 껍데기**(`updateFromServerCommand`) — `updateZipCommand` 와 같은 뼈대

1. NEEDS `["signedIn","tenant","site","siteMatches"]` — 「zip 으로 교체」와 동일.
2. `ensureApiFor()` 캡처 → `listRevisions` → `pickRevision`(활성 우선 · 없으면 최신 READY).
   없으면 `noRevisionError`.
3. 이미 그 판이면 말하되 **막지 않는다**(사본이 망가져 다시 받는 경우 — 기존 선례).
4. **확인 모달**: 문면은 `say` 새 항목(사이트 이름·판 번호 포함).
   detail = ⑴ 표식이 있으면 「버전 N 에서 받아 작업하신 폴더입니다 → 버전 M 으로 교체합니다」
   (없으면 그 줄 생략 — 결여 관용) ⑵ 「지금 내용은 사라집니다」 ⑶ `keepNames` 목록 ⑷ 잔재가
   감지돼 있으면 그 사실. 전부 `plainNotice` 를 지난다.
   단추: **[버전 M 으로 갈아 끼우기]** · **[zip 으로 내보내기 먼저]**(누르면 export 를 부르고
   **진행하지 않는다** — 이어붙이기 상태기계를 안 만든다).
5. `stopPreview()` → `whileExtracting` + `withProgress` → 로그(파일 수·kept·표식 결과) →
   `refreshSidebar` → 완료 알림.

**자리**: 사이드바 「작업 폴더」 묶음, 「zip 으로 교체」 **바로 아래**. 「내려받기」 묶음은
불가 — 그 묶음의 툴팁·시험이 「있는 파일을 덮지 않는다」를 약속한다.

**이름·문면**: 라벨 「서버 판으로 교체」, 명령 id `zalkera.site.updateFromServer`.
툴팁은 **어느 판인지를 담는다** — 「지금 폴더를 지우고, 서버에 켜져 있는 판을 받아 그것으로
바꿉니다. 지금 내용은 사라집니다」.

## 5. 잔재 회수 — 같은 판, 이 형상으로

**같은 판이다.** 별건으로 미루면 「입구는 둘, 회수는 0」이 된다.

- **상수 단일화**: `replaceDir.ts` 가 `STASH_PREFIX` 를 수출하고 `mkdtemp` 와 감지기가 **같은 값**을
  쓴다(손 복제 목록이 갈리는 것이 이 레포의 반복 사고다).
- **감지**: core 순수 판정 `stashLeftovers(entryNames): string[]`. 확장이 창 활성화 때 1회,
  실경로의 부모를 **비동기** `readdir` 해서 넘긴다(활성화 동기 구간에 I/O 를 안 더한다).
- **안내**: 「지난 갈아 끼우기가 중간에 끊긴 흔적이 있습니다. 원래 소스가 〈경로〉 에 있습니다.
  옮기실 것을 옮긴 뒤 그 폴더를 지우시면 됩니다」 + [탐색기에서 보기]. 경로는 `plainNotice`.
  **억제 상태를 저장하지 않는다** — 잔재가 있는 한 창을 열 때마다 말한다.
- **진단**(`zalkera.doctor`)에 같은 판정 항목. **교체 모달**에도 병기.
- ⛔ **자동 삭제·자동 복원은 안 짓는다** — 잔재는 **원본의 유일 사본일 수 있다**(중단 시점에
  따라 폴더는 반쪽이다). 지우는 것은 제스처가 있어도 새 파괴면이고, 복원은 그 자체가 또 한 번의
  교체(같은 기계·같은 실패면)다.
- **문서 현행화(같은 트랜치)**: `help.md`·`MANUAL.md` 의 「확장이 그것을 찾아 주지는 못하니」가
  이 판에서 거짓이 된다 — 같은 커밋에서 고친다.

## 6. 보안 판정

- **교차 테넌트**: 캡처 테넌트 규율을 그대로 지난다. `siteMatches` 가 알려진 어긋남을 막고,
  소속 미상 폴더는 모달이 사이트 이름으로 고지된 동의를 받는다. 소스 출처가 **서버 정본(sha 대조)**
  이라 zip 문의 「출처 표시는 선언」 약점보다 강하다. 표식 쓰기는 `decideImportBinding` 을 지나
  남의 소속을 안 덮는다.
- **자격증명**: `keep` 이 zip 문과 같은 술어(`keepNames`)를 쓴다. 서버 tar 가 keep 이름과 겹치면
  쓰기 충돌 → 전체 되돌리기 — **조용한 진행이 아니라 시끄러운 실패**로 둔다(공유 해제기에 필터
  옵션을 늘리지 않는다).
- **파일 파괴**: 파괴 창 축소(네트워크 선행) + 기존 되돌리기·stash 재사용 + 즉사 잔재는 §5 가 받는다.
  감지기는 **표시만** 하고 지우지 않으므로 심링크 잔재 이름으로 파괴를 유도할 수 없다.
- **문면 주입**: 새 문면 전부 `say`/`plainNotice` 관할. 잔재 경로 알림 포함.

## 7. 판 등급과 영향

- **minor** — 새 명령·새 사이드바 항목·새 문면. CHANGELOG + 배송 문서 셋 갱신이 체크리스트다.
- **서버 선행 배포 규율 비적용** — 새 엔드포인트 0. `listRevisions`·`sourceUrl` 은 이미 상용에서 도는 문이다.
- **`@zalkera/client`·examples 영향 없음.**

## 8. 시험·검사기로 고정할 것 — «깨져도 초록»이 될 자리부터

1. **표식 미갱신이 최대 후보다** — 잊혀도 기능은 다 되는 것처럼 보이고 증상이 「발행마다 409
   동의」로 **멀리서** 난다. 그래서 표식 쓰기를 core 합성 안에 넣고, 시험이 「성공 후 표식 = 새
   판번호·새 sha」·「쓰기 실패 시 옛 표식 잔존」·「`keep`/`unknown` 이면 안 씀」을 직접 문다.
2. **잔재 상수 드리프트** — 접두만 바꾸면 감지기가 영원히 조용히 빈손이 된다(fail-open).
   상수 단일화에 더해 **실제 실패 경로로 잔재를 만들어** 감지기가 찾는 통합 시험을 둔다.
3. **해제 실패의 되돌리기** — `fill` 이 던졌을 때 폴더가 원상 복구됐는지 **내용까지** 대조한다.
4. **자리 고정** — 「내려받기」 묶음 시험이 이미 파괴 동사의 오배치를 문다. NEEDS 누락은
   `commandsWithNeeds` 대조가 멈춘다.
5. **문면 갈래** — 전수 스위프는 한 갈래만 본다(알려진 한계). 갈래별 명시 시험을 함께 둔다.
6. **한계(고정 아님)**: 전송 취소는 이 동사도 없다 — `fetchSiteSource` 의 기존 한계를 물려받는다.

## 9. DON'T-BUILD

- 병합·부분 교체·「내 변경만 남기고 갱신」 — git 수준.
- 더티 검출(표식 sha 로 폴더 내용 검증 포함) — 의미론이 틀렸다.
- 교체 전 자동 백업 · stash 자동 복원·자동 삭제 — 제스처 없는 쓰기·새 파괴면.
- elsewhere 화면에 이 동사 — 소속 변경+파괴 결합.
- 원격 새 판 감시(폴링·알림) — 사이드바 비용·인증 호출이 주파수를 탄다.
- 판 선택 UI 가 달린 교체 — 판정 두 벌 금지.

## 10. 미해결 쟁점

1. **롤백 상태의 사이트에서 이 동사 뒤 첫 발행** — `DECISIONS.md` 「열려 있는 쟁점 2」와 같은
   뿌리다. 이 동사는 그 결정을 물려받는다(막다른길은 아니고 동의 한 번).
2. ~~잔재 알림의 자리 수위~~ — **닫힘.** 창 활성화 알림까지 간다(오너 결정). 억제 상태는
   저장하지 않는다 — 잔재가 있는 한 창을 열 때마다 말한다.

## 11. Opus 검토 (구현 전)

설계가 부르는 심볼 열둘이 전부 실재함을 확인했다.
재현: `for s in fetchVerifiedSourceTar decideImportBinding pickRevision keepNames findProjectRoot
noRevisionError holdsSameRevision writeSourceMarkTo parseSourceMark whileExtracting stopPreview
extractTarGz; do grep -rn "function $s\|const $s" packages/*/src --include="*.ts"; done`

**R1 — 겹 흡수를 뺀다.** 설계는 해제 뒤 `findProjectRoot` 가 하위를 가리키면 한 단계 끌어올리자고
했다. 뺀다:

- **형제가 안 한다.** 같은 서버 tar 를 푸는 `fetchSiteSource` 는 그냥 푼다. 한쪽만 흡수하면
  **같은 산출물을 두 문이 다르게 다루게** 된다 — 이 레포가 반복해 앓은 「판정이 두 벌」이다.
- **전제가 미확인이다.** 설계 스스로 「서버 tar 가 한 겹 감싸는 경우가 실제로 있는지」를
  **확인 못 함**으로 분류했다. 확인 안 된 전제 위에 새 실패 경로(이름 충돌 → 전체 되돌리기)를
  얹는 것은 값이 안 맞는다.
- 감싸기가 실물로 드러나면 **공유 해제 자리 한 곳**에서 고친다 — 새 문에만 붙이지 않는다.

**R2 — 배송 문서 한 행이 더 있다.** `MANUAL.md` 의 「갱신 뒤 미리보기가 느리다 | `node_modules` 를
지우므로…」 행이 zip 어휘로만 적혀 있다. 이 명령도 같은 일을 하므로 그 행이 두 동사를 다 담아야
한다. 설계 §5 의 문서 목록에 이 행을 더한다.

**받아들인 것**: `preserve: [SOURCE_MARK_PATH]` 는 **하중을 받는다** — 표식 쓰기가 실패해도 옛
표식이 남아 소속을 안 잃는 것이 그 인자 덕이다. 지우지 않는다.

**한계로 남기는 것**: 이 동사도 전송 취소가 없다. 다만 **파괴가 전송 뒤**라 전송 중 창을 닫으면
폴더는 **그대로 남는다** — 순서가 이미 안전한 쪽이다. KDoc 에 그 사실을 적는다.

## 12. 3축 심의 (Fable) 와 이행

**보안 승인 · 성능 승인 · 기능 조건부.** 🔴 없음. 변이 5종이 전부 게이트에 물리는 것을 심의가 실증했다
(소독 제거 ×2 · 표식 쓰기 위장 · 스태시 접두 두 벌 · 잔재 알림 삭제).

§2 의 인과 사슬은 **로컬 구간이 닫힌다**는 것이 실측으로 확인됐다. 다만 한 가지가 정밀해졌다 —
발행 **성공**이 `PublishedMark` 를 다시 쓰므로 거짓 동의는 「영원히」가 아니라 **두-걸음 사이클마다 1회**다.
받아 맞추고→고치고→올리는 반복 워크플로에서는 매 사이클이라 존재 근거는 그대로 선다.

| 조건 | 이행 |
|---|---|
| **F1** 잔재 알림이 `siteDir()` 게이트라 **최악 사례에서 침묵**한다 — 교체가 일찍 죽으면 `package.json` 이 스태시 안이다. 배송 문서는 무조건으로 약속한다 | 게이트를 `workspaceDir()` 로 낮췄다. 이름만이 아니라 **전체 경로**를 말하고 [폴더 열기] 단추를 준다(숨은 dot 폴더는 탐색기 기본 설정에서 안 보인다). 배선으로 고정 |
| **F2** 판 목록이 형제와 갈린다(`REFLECT_PAGE=20` vs 전량) · `latest-ready` 무표기라 툴팁 「켜져 있는 판」이 그 갈래에서 거짓 | 전량 조회로 되돌리고 `say.pickedLatestReady` 를 형제와 같이 낸다. 배선으로 고정 |
| **F3** 메모 미현행화 + 기록 없는 이탈 셋 | 이 절이 그 기록이다(아래) |

**기록 없이 이탈했던 것 — 이제 적는다**

- **`zalkera.doctor` 의 잔재 항목은 안 지었다.** 창 활성화 알림이 같은 사실을 **더 이른 시점에** 말하고,
  진단은 「안 될 때 여는 곳」이라 이미 알림을 본 사람이 한 번 더 보는 자리다. 필요하면 나중에 더한다.
- **`holdsSameRevision` 은 안 썼다.** 모달이 「버전 N → 버전 M」을 이미 말하므로 같은 번호면 사람이 그
  줄에서 본다. 별도 문면을 더하면 같은 사실을 두 벌로 말하게 된다.
- **[폴더 열기] 단추는 F1 이행에서 들어왔다** — 설계 §5 가 요구한 것을 그때 빠뜨렸다가 심의가 잡았다.

## 확인 못 함

- 서버 tar 가 실물에서 한 겹 감싸는 경우가 실제로 있는지 — R1 로 이 판에서는 다루지 않는다.
- 서버의 base-moved 409 술어 실동작(상용 왕복) — 이 레포 밖이다.
- 백엔드 정본 tar 가 `keep` 이름(`.env` 류)을 실을 수 있는지 — 실리면 **시끄러운 실패**임은 심의가 실측했으나,
  실림 여부 자체는 이 레포 밖이다.

- 콘솔 업로드 경유 판의 tar 에 `.env` 류가 실릴 수 있는지(백엔드 포장 규칙은 이 레포 밖).
- §2 의 「두 걸음 → 발행마다 거짓 409 동의」는 코드 추적이며 상용 왕복 실측이 아니다.
