# 설계 메모 — zip 수령 입구와 사이트 전환 운용

> 요구(정본): 거래처 홈페이지 이관 후 오너가 zip 을 받아 열고, 사이트를 번갈아 오가며
> 미리보기·배포한다. 하루에 여러 번: zip 받기 → 열기 → 연결 → 미리보기 → 올리기 → 다음 거래처.
> 이 메모는 세 축을 판정한다 — **입구**(zip 으로 시작), **출구**(zip 으로 내보내기),
> **전환 편의**(0.3.0 흐름의 클릭 수).

## 1. 현 상태 (코드 사실)

- 명령 18개. 재현: `grep -c 'register("zalkera\.' packages/vscode/src/extension.ts` → 18.
- 소스 입구는 셋 — 예제로 시작(`startFromPreset`)·사이트 소스 받기(`fetchSiteSource`)·폴더 연결.
  로컬 zip 을 받는 입구는 없다.
- `startFromPreset`(`packages/core/src/presets.ts`): 빈 폴더 강제(`meaningfulEntries`) →
  상한 있는 다운로드(`downloadBounded`) → **sha256 fail-closed**(해시 부재도 거절) → `extractZip` →
  실패 시 `removeAdded` 롤백. `fetchSiteSource`(tar 경로)도 같은 형상이다.
- `extractZip`(`packages/core/src/unzip.ts`): 중앙 디렉터리 파싱 · `MAX_ENTRIES`·`MAX_ENTRY_BYTES`·
  `MAX_EXTRACT_BYTES`(폭탄) · `safeSegments`+`descend`(zip-slip·심링크) · `writeExclusive`
  (기존 파일·중복 항목 구분). 로컬 zip 에 그대로 쓸 수 있는 방어다.
- **`__MACOSX` 처리 없음.** 재현: `grep -rn "MACOSX" packages/core/src` → 0건.
  발행 제외 목록에도 없다: `grep -in "macosx" packages/core/src/zip.ts` → 0건.
- **중첩 단일 루트 흡수는 받기(tar) 경로에만 있다** — 해제 **후** `findProjectRoot`
  (`packages/core/src/fetchSource.ts`)를 `openSite` 가 부른다. zip(프리셋) 경로는 부르지 않는다.
  재현: `grep -n "findProjectRoot" packages/vscode/src/extension.ts packages/core/src/fetchSource.ts`
- 발행 제외(`packages/core/src/zip.ts`): `ALWAYS_EXCLUDED`(이름 단위 — `node_modules`·`.git`·
  `.vscode`·`.mcp.json`·`.ssh`·`.aws` 등)·`EXCLUDED_PATHS`(`.zalkera/source.json`)·
  `isSecretFile`(`.env` 접두 전부 + 표준 자격증명 파일명·확장자). 뺀 것은 이름을 대고 보고한다.
  재현: `grep -n "ALWAYS_EXCLUDED\|EXCLUDED_PATHS\|isSecretFile" packages/core/src/zip.ts`
- 0.3.0 소속 형상: 표식(`.zalkera/source.json`)이 정본, `decideBlocked` 의 `siteMatches` 게이트,
  `folderRegistry`(globalState 캐시·확증 필수), `decideSiteChoice` 의 폴더 전환 제안,
  `linked`/`published` 표식(format 2). 정본 문서 `doc/DESIGN-site-folder-binding.md`.
- dev 서버 포트는 OS 가 배정한다(`pickPort` 의 `listen(0)` — `packages/core/src/dev.ts`).
  발급 키 저장은 창별 다중 미리보기를 전제한다(`issuedKeys.ts`).

## 2. 입구 판정 — 「zip 으로 시작」이 옳은 형상이다

오너 운용의 첫 동작이 「거래처 소스 zip 을 받는다」이고, 그 zip 이 로컬 프리뷰·발행 루프의
입력이다. 이 도구의 위협 모델은 처음부터 「zip 은 언제나 적대적일 수 있다」이므로
(`npmBlindSpots` 의 근거 문장), 그 zip 을 여는 자리도 도구의 방어 안에 있어야 한다.
이 입구는 체크리스트의 **업로드=정본입구** 칸을 전진시킨다 — 발행(`publish.ts`)이 콘솔 업로드와
같은 파이프라인이라, 「zip 으로 시작 → 미리보기 → 올리기」가 곧 로컬 검수 단계가 앞에 붙은
업로드 레인이다.

기각한 대안과 사유:

- **⑴ 수동 압축 해제 + 「폴더 연결」** — 기각.
  - OS 해제기는 zip-slip·압축 폭탄·심링크·중복 항목 방어가 없다. 도구가 세운 위협 모델을
    입구에서만 사람 손에 맡기는 형상이다.
  - `__MACOSX`·`.DS_Store`·중첩 루트가 폴더에 남는다. `.DS_Store` 는 발행이 빼지만
    `__MACOSX` 는 발행 제외 목록에 없어 **정본에 실린다**(§1 재현). 보낸 쪽의
    `.zalkera/source.json`·`.vscode/settings.json` 도 살아남아 새 폴더가 남의 소속을 물려받는다.
  - 하루 여러 번 반복하는 사람에게 수동 단계가 곧 실수 표면이다.
- **⑵ 콘솔에서 zip 업로드 → 「사이트 소스 받기」** — 기각.
  - 검수 전 소스가 원장에 판으로 남는다. 프리뷰는 정본화 **앞**에 있어야 하고, 이 순서가
    시작 소스 팩의 「발행 전 검수」와 같은 원칙이다.
  - 왕복 2회(업로드 후 다시 다운로드)·도구 2개. 서버 정규화·sha·format 1 표식의 이점은
    발행 뒤 「사이트 소스 받기」로 언제든 얻는다 — 선불로 낼 이유가 없다.

## 3. 입구 형상 설계

### 3.1 명령 흐름 — `zalkera.site.importZip` 「zip 으로 시작」

1. **zip 파일 고르기**(`showOpenDialog`, `filters: {"압축 파일": ["zip"]}`).
2. **크기 상한을 읽기 전에 본다** — `stat` 으로 `MAX_DOWNLOAD_BYTES`(150MB, `limits.ts`) 초과면
   사람 말로 거절. 로컬 파일이라고 다른 값을 만들지 않는다 — 해제 상한(`MAX_EXTRACT_BYTES`)이
   이 값에서 유도되는 사슬을 그대로 탄다.
3. **판정 먼저, 대화 나중.** zip 을 읽어 중앙 디렉터리의 이름 목록을 뽑고
   `decideImportPlan`(§3.2)을 지난다. 거절이면 **대상 폴더를 고르게 하기 전에** 끝난다 —
   아무것도 쓰지 않았고, 헛수고도 시키지 않았다.
4. **빈 폴더 강제** — `meaningfulEntries`(형제 두 입구와 같은 규율·같은 문면). 대상 폴더 대화는
   `startFromExample` 의 것을 그대로 쓴다.
5. **해제** — `extractZip` 재사용 + 플랜 적용(§3.3). 실패 시 `removeAdded` 롤백(형제 규율 —
   배송 문서의 「폴더는 그대로입니다」 보증이 이 경로에도 걸린다).
6. **연결 단계(선택)** — `listMyTenants` QuickPick 「이 소스는 어느 사이트의 것입니까?」
   + 「나중에 정하기」. 연결하면 §3.5 의 세 가지를 쓴다. 새 폴더에는 소속이 없으므로
   재연결 동의 모달은 뜨지 않는다(`needsRelinkConsent` 가 `binding === null` 에서 이미 false).
7. **「이 폴더 열기」 제안**(형제 입구와 같은 마무리).

재진입은 `withReceiveGuard` 를 형제 둘과 **같이** 쓴다 — 같은 폴더에 아카이브를 푸는 일이라
어느 조합이든 겹치면 안 된다는 기존 근거 그대로다.

### 3.2 순수 판정 `decideImportPlan` — core, 쓰기 전

새 파일 `packages/core/src/importZip.ts`. 입력은 항목 이름 목록, 출력은:

```ts
type ImportPlan =
    | { ok: true; root: string; dropped: string[] }   // root: 벗길 접두("" 가능) · dropped: 안 푸는 항목
    | { ok: false; reason: "empty" | "not-a-site" };
```

판정 순서:

1. **제외** — 발행이 정본에 싣지 않는 것은 들여오지도 않는다. `zip.ts` 의 `ALWAYS_EXCLUDED`
   (이름 단위)·`EXCLUDED_PATHS`(경로 단위)를 **같은 상수로 재사용**한다(export 해서 import —
   목록 두 벌은 반드시 갈린다). 이것이 부수로 해결하는 것:
   - `__MACOSX/`(§3.4 에서 목록에 추가) — Finder 압축 부스러기.
   - 보낸 쪽 `.zalkera/source.json` — 남의 소속 표식이 새 폴더에 실리지 않는다. 수령 폴더는
     **소속 없음으로 시작**하고, 소속은 연결 단계(§3.5)나 발행 결정화(기존 §4.6)로만 생긴다.
   - 보낸 쪽 `.vscode`(`zalkera.tenant` 링크)·`.mcp.json`·`node_modules`(항목 수 상한을 혼자
     채울 수 있는 부피)·`.git` — 발행 제외 KDoc 이 이미 적어 둔 그 이유들이 방향만 바뀐 채 성립한다.
2. **단일 루트 반복 흡수** — 남은 항목의 첫 조각이 하나뿐인 디렉터리면 벗기고 반복한다
   (`site/site/...`). `findProjectRoot` 의 판정을 **해제 전**으로 옮긴 것이다 — 해제 후 옮기기가
   아니라 처음부터 뿌리에 쓰므로, 표식·링크·레지스트리가 적히는 폴더와 열리는 폴더가 같다.
3. **not-a-site 거절** — 흡수된 뿌리에 `package.json` 이 없으면 거절. `siteDir()` 과 같은
   잣대다. 더 강한 판정(`@zalkera/client`·next 유무)은 **걸지 않는다** — 이관 소스는 원본
   그대로 옮기는 것이 원칙이고, client 선언 없는 사이트를 `precheck` 도 정상으로 본다
   (`packages/core/src/precheck.ts`). 그 층위는 풀고 난 뒤 조언으로 남긴다.

`dropped` 는 **이름을 대고 보고**한다(발행 쪽 「비밀로 판단해 뺀 파일」 보고와 같은 규율 —
조용히 빼지 않는다).

### 3.3 `extractZip` 확장 — 판정은 플랜이, 실행은 해제기가

`extractZip(zip, targetDir, plan?)` 로 선택 인자를 더한다. 해제기는 항목마다 ⑴ 플랜의 제외에
걸리면 건너뛰고 ⑵ `root` 접두를 벗긴 뒤 ⑶ **벗긴 이름으로** 기존 안전 검사 전부
(`safeSegments`·`assertNotVendored`·`descend`·`assertNotSymlink`·`writeExclusive`·총량 상한)를
지난다. 순서가 요점이다 — 흡수·제외가 안전 검사 **앞**에서 이름을 바꾸므로, 검사는 반드시
실제로 쓸 경로를 봐야 한다(§10 의 변이 시험이 이것을 박는다).

플랜을 안 넘기면 현행과 동작이 같다. **`startFromPreset` 은 플랜을 켜지 않는다** — 팩은 발행 전
검수를 지난 산물이라, `__MACOSX`·중첩 루트가 든 팩은 흡수해 줄 것이 아니라 검수가 반려할
결함이다. 흡수를 켜면 그 결함이 조용히 가려진다. `fetchSiteSource`(tar) 도 무변경 —
정본 tar 는 서버가 정규화하고, 현행 `findProjectRoot` 후처리가 이미 선다.

### 3.4 사라진 sha256 자리 — 무엇으로 대신하는가

서버 입구의 sha256 은 「원장의 그 바이트다」라는 주장을 검증했다. 로컬 zip 에는 **그 주장
자체가 없다** — 대조할 원본이 어디에도 없고, 신뢰 근거는 파일을 건넨 사람이다. 그래서 검증을
다른 수단으로 흉내 내지 않고, 자리를 이렇게 채운다:

- **fail-closed 는 구조 판정으로** — zip 형식 오류·상한 초과·not-a-site 는 전부 **아무것도
  쓰기 전에** 거절한다(§3.1 순서).
- **주장하지 않는다** — 완료 문면·로그 어디에도 「검증했다」「원본과 같다」류를 넣지 않고,
  format 1 표식(받기 사건의 기록·판 주장)을 **쓰지 않는다**. 검증이 있는 척하는 것이 없는 것보다
  나쁘다는 `presets.ts` 의 판정을 역방향으로 적용한 것이다.
- 부수 강화: `ALWAYS_EXCLUDED` 에 `__macosx` 를 추가한다(조회가 소문자라 **항목도 소문자** —
  그 파일 KDoc 의 `.DS_Store` 함정 그대로). 수동 해제 레인으로 들어온 폴더의 발행도 함께
  깨끗해진다.

### 3.5 푼 뒤 — 표식·링크·레지스트리 (0.3.0 형상과의 맞물림)

- **해제 직후에는 아무것도 쓰지 않는다.** 그 시점의 폴더는 어느 사이트의 소스도 아니다 —
  `startFromExample` 과 같은 규율이고, 표식 부재는 게이트가 막지 않는다(localMark 의
  「부재는 정상이다」).
- **연결 단계에서 연결하면** 「폴더 연결」의 쓰기 세 가지를 그대로 한다:
  ⑴ `writeBindingMarkTo(root, {origin: "linked", tenant, linkedAt})` — 판 주장이 없는 표식.
  이 폴더가 어느 판의 사본인지 도구는 모르므로 `linked` 가 정확하다.
  ⑵ `linkFolderToTenant(root, tenant)` — 워크스페이스 링크. 대상 폴더는 아직 안 열려 있으므로
  `openSite` 가 새 폴더에 하듯 파일로 직접 쓴다(설정 API 는 열린 창에만 닿는다).
  ⑶ `rememberFolder(tenant, root)` — 레지스트리. 이로써 다음 「사이트 선택」의 폴더 전환
  제안(§4.4 형상)이 이 폴더를 찾는다.
- **「나중에 정하기」면** 셋 다 안 쓴다. 소속은 나중에 「폴더 연결」 또는 발행 결정화가 정한다.
- 연결 단계가 있는데도 게이트가 안전한 이유: 어긋난 값을 적을 길이 없다 — 소속 없는 새 폴더에
  적는 첫 값이므로 `siteMatches` 가 곧바로 그 값을 지킨다.

### 3.6 `startFromPreset` 과의 공유·차이 정리

| 자리 | 예제로 시작 | zip 으로 시작 |
|---|---|---|
| 빈 폴더 강제 | `meaningfulEntries` | 같음(같은 문면) |
| 입수 | `downloadBounded`(상한·주소 검사) | 로컬 읽기 + `stat` 상한(같은 상수) |
| 무결성 | sha256 fail-closed | 없음 — 구조 fail-closed + 무주장(§3.4) |
| 해제 | `extractZip` | 같음 + 플랜(제외·흡수) |
| 롤백 | `removeAdded` | 같음 |
| 재진입 | `withReceiveGuard` | 같음(같은 가드) |
| 푼 뒤 쓰기 | 없음 | 없음, 단 연결 단계가 선택으로 붙음(§3.5) |

## 4. 출구 판정 — 「zip 으로 내보내기」는 이연한다

### 4.1 보안 판정 (채택 여부와 무관하게 명시한다)

폴더를 OS 로 그냥 압축하면 `.env.local`(우리가 발급한 미리보기 키 — 서버 TTL 최대 12시간)·
`.mcp.json`(관례상 `env: { GITHUB_TOKEN: … }` 를 든 서버 항목)·`.ssh`·`.aws` 사본·기타
자격증명 파일이 그대로 실린다. 그 zip 이 개발자·오너 손을 거쳐 유통되면 **고객 자격증명이
유통되는 것**이다.

`zip.ts` 는 이것을 이미 안다 — `ALWAYS_EXCLUDED` 가 위 넷을 이름으로 빼고, `isSecretFile` 이
`.env` 접두 전부와 표준 자격증명 파일명·확장자를 걸러 **이름을 대고 보고**하며,
`EXCLUDED_PATHS` 가 소속 표식을 뺀다(§1 재현 명령). `packProject` 는 `projectDir` 만 받는
파일 API 이고 `writeZip` 도 이미 있으므로, **내보내기가 그 함수를 그대로 재사용할 수 있다** —
채택하게 되면 재사용이 선택이 아니라 필수다. 손 압축의 위험은 배송 문서에 한 줄로 적는다:
「폴더를 직접 압축해 보내면 `.env.local` 의 자격증명이 같이 나갑니다」.

### 4.2 이연 근거

- 요구 정본(오너 문장)의 흐름은 zip 이 **들어오는** 쪽이다.
- 로컬 폴더의 zip 은 원장 판과 다른 바이트의 **제3 유통 경로**다 — 판 번호도 원장 sha 도 없다.
  소스 유통의 정본 경로는 원장이다: 발행된 판을 「사이트 소스 받기」로 받거나 콘솔에서 받는다.
  고객·개발자에게 소스를 건네는 요구는 그 경로 위에서 푸는 것이 맞다.
- 목표 방향의 「개발자 zip 유통」은 미구현이 gap 이 아니며, 뜨는 날의 재판정 후보는
  정본 판 기반(서버) 대 로컬 `packProject` 기반이다(§11).

### 4.3 채택하게 되면 (형상만 박아 둔다)

「zip 으로 내보내기」 = `packProject` → `writeZip`(사용자 선택 위치) + `dropped` 보고 그대로 표시.
**`precheck` 를 강제하지 않는다** — precheck 의 헌장이 「조언이지 차단이 아니다」이고, 서버가
받아 줄 것을 확장이 먼저 막지 않는다는 원칙(그 파일 머리말)이 내보내기에도 그대로 선다.
완료 문면에 「배포 전 검사」를 권하는 한 줄만 싣는다. 자리는 사이드바 「내보내기」 묶음.

## 5. 전환 편의 — 실측과 개선

### 5.1 현행 클릭 수 (0.3.0 · 두 사이트 모두 로컬본 있고 레지스트리 확증되는 경우)

| 단계 | 행동 | 성격 |
|---|---|---|
| 1 | 사이드바 「사이트」의 현재 사이트 항목 클릭 | 클릭 |
| 2 | QuickPick 에서 다음 거래처 선택 | 클릭 |
| 3 | 비-모달 토스트의 「그 사이트 폴더 열기」 | 클릭 — **사라지는 표면.** 놓치면 아무 일도 없고 1부터 다시 |
| 4 | 미리보기 도는 중이면 모달 「폴더 열기」 | 클릭 |
| 5 | 창 전환 뒤 「미리보기 시작」 | 클릭 + 준비 대기 |

전환 한 번에 4~5클릭 + 대기 2회(창 전환·미리보기 준비). 하루 대여섯 번이면 20클릭대이고,
반복 마찰의 본체는 3의 토스트 유실과 5의 미리보기 재기동이다.

### 5.2 채택하는 개선 셋

- **① 사이트 QuickPick 직행.** 확증된 로컬본이 있는 사이트는 QuickPick `detail` 에
  「로컬본: <경로> — 고르면 그 폴더를 엽니다」를 적고, 고르면 **토스트 없이** 폴더를 연다.
  누른 시점의 재확증(`confirmedFolderFor`)은 유지한다 — 0.3.0 의 「기억만 믿고 열지 않는다」
  그대로. 동의는 항목 문면이 나른다 — 무엇이 일어날지 읽고 고른 것이므로 몰래 열기가 아니다.
  확증 안 되는 사이트는 현행 제안 흐름(받기)으로 남는다. 3단계가 사라져 **2클릭**이 된다.
- **② 미리보기 중 「새 창으로 열기」.** 현행 모달(「폴더를 열면 지금 미리보기는 멈춥니다」)에
  선택지를 더한다: 「이 창에서 열기」(현행) · 「새 창으로 열기」(`forceNewWindow: true` —
  이 창의 미리보기가 계속 돈다). 근거: dev 포트는 OS 배정이라 충돌하지 않고(`pickPort` 의
  `listen(0)`), 발급 키 저장은 창별 다중 미리보기를 전제한다(`issuedKeys.ts` — 창 사이 공유
  목록·창마다 켬). 창 둘을 띄워 두면 이후 같은 두 거래처의 왕복은 **OS 창 전환 = 0클릭**이고
  미리보기 재기동 대기도 없다. 단계 수가 늘지 않는다 — 이미 있는 모달에 버튼 하나가 는다.
- **③ 상태바 사이트 표시.** 둘째 상태바 항목 `$(account) <코드>` · 클릭 = 「사이트 선택」.
  어긋난 폴더(`siteMatches` 판정과 같은 조건)면 경고 배경. 판정은 core 의 순수 함수
  `statusBarPlan(state)`(`sidebarPlan.ts` 동거 — 시험이 물게)로 두고, 갱신은 `refreshSidebar`
  가 같이 한다(게이트·사이드바와 **같은 값** — `folderTenant` 공급 배선 횟수가 는다).
  사이드바를 안 연 화면에서도 「지금 어느 거래처인가」가 보인다 — 여러 사이트를 번갈아 다루는
  운용에서 제일 비싼 실수(다른 사이트에 대고 작업)를 화면 상시 표면이 줄인다.

### 5.3 기각한 편의안

- **최근 사이트 별도 목록/명령** — QuickPick 이 이미 전체 목록이고 ①이 로컬본 표시를 더한다.
  레지스트리는 캐시이지 UI 자료가 아니다(0.3.0 판정 유지).
- **폴더 자동 열기(제안 없이)** — 사용자 제스처 없는 창 전환. ①의 직행은 항목 문면이 예고를
  나르는 제스처 경로라서 다르다.
- **미리보기 자동 시작(폴더 열린 직후)** — 제스처 없는 자격증명 발급 + 첫 실행 수 분짜리 설치.
  ②의 새 창 유지가 같은 목적(재기동 대기 제거)을 부작용 없이 채운다.

## 6. 명령·사이드바·요건

| 명령 | 팔레트 제목 = 사이드바 라벨 | 묶음 | `NEEDS` |
|---|---|---|---|
| `zalkera.site.importZip`(신설) | zip 으로 시작 | **불러오기** | `["signedIn"]` |

- **사이드바 배치**: 소스 없는 상태의 「불러오기」에 넷째 항목으로 — 순서는
  예제로 시작 · 사이트 소스 받기 · **zip 으로 시작** · 폴더 연결(서버발 둘 먼저, 로컬발 둘 나중).
  **소스 있는 상태에도 「사이트 소스 받기」 옆에 보인다** — 오너의 주 흐름이 「어느 거래처
  폴더가 열린 창에서 다음 거래처 zip 을 받는」 것이고, 이 명령은 받기와 똑같이 새 빈 폴더로만
  가므로 묶음 툴팁의 「지금 폴더는 바뀌지 않습니다」가 그대로 덮는다. 숨김 유지 대상은
  기존대로 예제로 시작·폴더 연결이다(내 것이 날아가나를 다시 계산하게 만드는 둘).
- 묶음 툴팁 「셋 중 하나로 시작합니다」는 개수 없는 문장(「하나를 골라 시작합니다」)으로 바꾼다 —
  개수 주장은 항목 하나에 낡는다. `media/help.md` 의 「셋 중 하나」 절도 같은 트랜치에서 고친다.
  재현: `grep -n "셋 중" packages/core/src/sidebarPlan.ts packages/vscode/media/help.md`
- 라벨·팔레트 일치는 `check-sidebar-labels.mjs` 가 집행한다 — `package.json`
  `contributes.commands` 등재가 필수이고, 라벨은 두 자리에 같은 문자열로 적는다.
- **요건 판정**:
  - `signedIn` 만 단다. 해제 자체는 서버가 필요 없지만 연결 단계가 목록을 받아 오고,
    로그인 차단 문면의 action(`zalkera.signIn`)은 요건이 없어 고리가 없다.
  - `tenant` 를 달지 않는다 — 연결 대상은 명령이 스스로 목록을 받는다. `site.link` 가 같은
    이유로 `tenant` 를 빼며 지킨 고리 회피가 이 명령에도 그대로 성립한다.
  - **`siteMatches` 를 달지 않는다** — 이 명령은 새 빈 폴더로 가므로 현재 폴더의 소속과
    무관하고, 어긋난 창에서 다음 거래처의 zip 을 여는 것이 정상 사용이다. 달면 어긋난 창이
    새 작업의 입구까지 잃는다. `site.open`(같은 「새 폴더행」 명령)도 안 달고 있는 형상과 같다.
  - `NEEDS` 등재로 `whyBlocked.test.ts` 의 순회 시험(요건 충족 시 통과·차단 문면의 action
    비차단·무한 고리)이 자동으로 이 명령을 문다.

## 7. 보안 판정

### 7.1 막는 것

- zip-slip·심링크 경유 쓰기·압축 폭탄·중복 항목 덮어쓰기 — `extractZip` 재사용으로 로컬 zip 에도
  그대로. 수동 해제 대비 이 입구가 존재하는 이유의 절반이다.
- 발행 zip 의 `__MACOSX` 오염 — `ALWAYS_EXCLUDED` 추가(§3.4). 수동 해제 레인까지 소급해 막는다.
- 실려 온 남의 소속(`source.json`·`.vscode` 링크)·남의 MCP 항목(`.mcp.json`) — 제외 목록
  재사용(§3.2)으로 수령 폴더가 물려받지 않는다.
- 흡수·제외가 안전 검사를 우회하는 것 — 검사가 벗긴 이름(실제 쓸 경로)을 보는 순서 고정(§3.3·§10).
- 자격증명이 실린 zip 의 재유통 — 발행 쪽 `isSecretFile`·`ALWAYS_EXCLUDED` 가 이미 막고 있고,
  출구 이연(§4)이 로컬 zip 유통 경로 자체를 만들지 않는다.

### 7.2 못 막는 것 (정직하게 적는다)

- **zip 내용물의 적대성** — dev 서버는 그 폴더의 코드를 실행한다. 이 도구가 이미 전제하는
  위협이고 이 입구로 달라지지 않는다.
- **실려 온 보낸 쪽 비밀 파일**(`.env.local` 등 — 제외 목록·비밀 판정에 안 걸리는 자리 포함) —
  막지 않는다. 고객 사이트가 미리보기에 실제로 쓰는 값일 수 있고, 지우면 「원본 그대로」가
  깨진다. 발행 쪽 `isSecretFile` 이 재유출은 막고, 미리보기의 관리 칸은 다음 미리보기가
  이 폴더의 사이트 값으로 덮는다(`mergeEnv`). 이름 보고(조언)는 선택 트랜치로 심의에 올린다(§11).
- **zip 의 출처** — 검증할 수 없고, 검증한다고 주장하지 않는다(§3.4).

## 8. `@zalkera/client` · examples 판정

**둘 다 변경 불필요. 이번 건은 devtools 단독이다.**

- `@zalkera/client`: 불필요. zip 수령·해제·전환은 편집기 도구의 관심사이고, client 의
  계약면(런타임 API·env 변수 이름)을 건드리지 않는다. `llms.txt` 도 무변경 — 바이트 대조
  판올림 사유가 없다. 재현: `grep -rn "__MACOSX\|importZip" ../zalkera-client/src` → 0건.
- examples(시작 소스 팩): 불필요. 팩 zip 은 명시 목록으로 조립되고 서버가 유통하므로
  `__MACOSX`·중첩 루트가 실릴 경로가 없다 — 실렸다면 검수가 반려할 결함이고,
  `startFromPreset` 이 흡수를 켜지 않는 이유(§3.3)와 같은 판정이다.

## 11. 미해결 쟁점 (심의 회부)

1. 제외 목록의 `.vscode` — 보낸 쪽 편집기 설정 폐기가 「원본 그대로 이관」과 충돌하는가.
   본 메모는 발행 제외와 같은 근거(편집기 설정은 사이트 내용이 아니다·소속 링크 오염 방지)로
   폐기 판정.
2. QuickPick 직행이 토스트 확인 단계를 없애는 것 — 동의 표면 축소로 볼지. 본 메모는 항목
   `detail` 문면이 예고를 나르는 제스처 경로로 판정.
3. 「새 창으로 열기」의 동시 미리보기 — 창별 발급 키 동시 수에 대한 서버 정책 확인(확장 쪽
   저장은 다중을 전제하나 서버 발급 상한은 이 레포 밖이다).
4. 실려 온 비밀 모양 파일의 이름 보고(조언·비차단) 트랜치 포함 여부.
5. 출구 이연의 재판정 시점 — 개발자 zip 유통 요구가 실제로 뜨면, 정본 판 기반(서버 내려받기)
   대 로컬 `packProject` 기반을 그때 다시 판정한다. 어느 쪽이든 §4.1 의 재사용 원칙은 유지.
