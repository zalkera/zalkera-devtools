# 잘커라 확장 사용 매뉴얼

VS Code 에서 사이트 소스를 받아 고치고, 미리 보고, 올리는 도구입니다.
확장 안에도 도움말이 있습니다(`잘커라: 도움말`) — 그쪽은 **사전**이고 이 문서는 **작업 순서**입니다.

---

## 1. 처음 한 번

```bash
code --install-extension zalkera.zalkera-devtools --force
```

깔면 왼쪽에 잘커라 아이콘이 생깁니다. **로그인** → **사이트 선택** 순으로 누르십시오.
맡으신 사이트가 여럿이면 그다음부터 그 자리가 **사이트 전환**으로 바뀝니다.
그다음부터는 사이드바가 지금 할 수 있는 것을 보여 줍니다.

> **Node.js 는 따로 까시지 않아도 됩니다.** 없으면 없는 대로 미리보기가 뜹니다.
> ⚠ 오히려 **낡은 Node.js 가 깔려 있으면 안 뜰 수 있습니다** — 아래 §5 를 보십시오.

## 2. 매일 쓰는 것들

| 하려는 일                              | 누르는 것             | 묶음      |
| -------------------------------------- | --------------------- | --------- |
| 배포 중인 소스를 **폴더로**            | **소스 다운로드**     | 내려받기  |
| 배포 중인 소스를 **파일 하나로**       | **소스 zip 다운로드** | 내려받기  |
| 예제를 파일 하나로                     | **예제 zip 다운로드** | 내려받기  |
| 이 창을 **다른 폴더로** 옮김           | **작업 폴더 변경**    | 작업 폴더 |
| 받은 zip 으로 **새로** 시작            | **zip 으로 시작**     | 작업 폴더 |
| 받은 zip 으로 **지금 폴더를 갈아 끼움**| **zip 으로 교체**     | 작업 폴더 |
| **서버 판으로** 지금 폴더를 갈아 끼움  | **서버 판으로 교체**  | 작업 폴더 |
| 화면 확인                              | **미리보기 시작**     | 미리보기  |
| 올리기 전 점검 · 올리기                | **배포 전 검사** · **새 버전 배포** | 배포 |
| AI 에게 **내 데이터**를 열어 줌         | **내 데이터 보여 주기** | AI 연결 |

「내려받기」 셋은 파일로 받거나 **빈 폴더**로 갑니다. 소스가 들어 있는 폴더는 건드리지 않고
옆에 새 폴더를 만들어 드립니다. 빈 폴더를 열어 두셨다면 **그 폴더에 받으시겠는지 먼저
여쭙습니다.**

소스가 들어 있는 폴더를 **덮어쓰는 것**은 「작업 폴더」의 **zip 으로 교체**와
**서버 판으로 교체** 둘입니다. 재료만 다릅니다 — 받으신 zip 이냐, 서버에 켜져 있는 판이냐.

> 「소스 다운로드」와 「소스 zip 다운로드」는 **같은 판**을 받습니다. 다른 것은 결과의 모양뿐입니다 —
> 앞은 바로 고칠 수 있는 폴더, 뒤는 남에게 넘기거나 보관할 파일 하나입니다.

명령 팔레트는 `Ctrl/Cmd + Shift + P` 입니다. 「zalkera」로 검색하면 전부 나옵니다.

**「새 버전 배포」를 누르면 손님이 보는 사이트가 바뀝니다.** 누르기 전에 「미리보기 시작」으로
확인해 주십시오. 잘못 올리셨으면 「버전 전환」에서 이전 판을 고르시면 그때로 돌아갑니다.

올리는 중에 **그만두실 수 있습니다.** 보내는 도중에 멈추시면 새 버전은 만들어지지 않습니다.
서버가 확인을 시작한 뒤에 누르시면 그 버전이 만들어졌을 수 있고, 그때는 기다리기만 그만두는
것입니다. 결과를 못 받았으면 단정하지 않고 연결 오류로 알려 드립니다.

## 3. 주의 사항

### 되돌릴 수 없는 것 — 둘입니다

**`zip 으로 교체`**·**`서버 판으로 교체`** 는 지금 폴더의 내용을 지웁니다. 확인 창이 한 번 뜨고,
거기서 무엇을 남기는지 보여 드립니다.

**`서버 판으로 교체`**의 확인 창에는 **「zip 으로 내보내기 먼저」** 단추가 있습니다 — 지금 폴더를
챙겨 두고 싶으실 때 누르시면 내보내기로 가고, 갈아 끼우지는 않습니다.
⚠ **`zip 으로 교체`에는 그 단추가 없습니다.** 챙겨 두시려면 **먼저** 「zip 으로 내보내기」를
누르신 뒤에 교체하십시오.

- **그대로 두는 것**: `.git` · `.env`·`.env.local` 같은 실제 환경 파일 · `.vscode` · `.idea` ·
  `.ssh` · `.aws` · `.npmrc` · `.mcp.json` · `.claude` · 인증서 파일
- **`.env.example` 류는 남기지 않습니다** — 소스의 일부라 받으신 zip 의 것으로 바뀝니다
- **지우는 것**: 그 밖의 모든 파일. `node_modules`·`.next` 같은 다시 만들어지는 것도 지웁니다
- **폴더 바로 아래만 지킵니다** — 하위 폴더 안의 `.env.local` 은 못 지킵니다

> **로컬에서 직접 고치신 것이 있으면 갱신 전에 빼 두십시오.** 없어집니다.
> 지금 상태를 통째로 보관하시려면 **zip 으로 내보내기** 를 먼저 쓰십시오.

갈아 끼우다 **실패로 멈추면** 원래 소스로 되돌립니다. 되돌리기까지 실패하는 드문 경우에는
**원래 소스가 어디 있는지** 알려 드리니, 그 경로에서 손으로 옮기시면 됩니다.

> ⚠ **갈아 끼우는 동안에는 창을 닫지 말아 주십시오.** 그 중간에 편집기가 꺼지면 되돌리기가
> 돌지 못합니다. 그때는 폴더 **옆에** `.zalkera-stash-` 로 시작하는 숨은 폴더가 남고 원래 소스가
> 그 안에 있습니다 — 확장이 그것을 찾아 주지는 못하니 직접 보셔야 합니다.

### 조용히 어긋나는 것

**폴더마다 자기 사이트를 기억합니다.** 그래서 사이트를 바꾸는 것은 **폴더를 바꾸는 일**입니다.
사이드바에서 다른 사이트를 고르면 지금 폴더는 그대로 두고, 어떻게 갈지 고르는 화면을 드립니다.

상태바 왼쪽 아래에 **지금 작업 사이트**가 보입니다. **올리기 전에 여기를 한 번 보십시오.**
⚠ 미리보기가 도는 동안에는 그 자리를 미리보기가 씁니다 — 그동안은 사이트 이름도 경고색도
안 보입니다.

### 미리보기는 진짜 데이터를 봅니다

미리보기는 **상용 데이터를 읽습니다.** 화면에 보이는 상품·주문은 진짜입니다.

자리를 비우실 때는 **미리보기 중지** 를 눌러 주십시오. 중지는 내 컴퓨터의 서버를 멈춥니다 —
서버 열쇠는 유효기간(최대 12시간)까지 살아 있으니, 지금 없애시려면 **로그아웃**하십시오.

### AI 연결이 여는 것

「AI 연결」을 켜면 쓰시는 AI 가 **잘커라 서버에 붙습니다.**

| | AI 가 할 수 있게 되는 것 |
| --- | --- |
| **내 데이터 보여 주기** | 상품·글·설정 **조회** · 소스 **읽기·고치기** · **새 버전 발행** · **이전 판으로 되돌리기** |

⚠ **발행은 손님이 보는 사이트를 바꿉니다.** AI 에게 「올려 줘」라고 말씀하시면 그 자리에서
바뀝니다 — 확인을 한 번 더 묻지 않습니다. 무엇이 바뀌는지 먼저 보시려면 **미리보기**로 확인한
뒤에 말씀하십시오. 잘못 나갔으면 사이드바 **「버전 전환」**에서 이전 판으로 돌아가시면 됩니다.

이 문을 안 여셔도 사이트는 그대로 굴러갑니다. **「내려받기」·「배포」·「버전 전환」**은 사이드바에
그대로 있고, 그쪽은 사장님이 직접 누르시는 자리입니다.

🔴 **AI 가 서버에서 고쳐 둔 것이 있으면 올리기가 막힙니다.** 그 편집은 발행 전 상태로 서버에
쌓이고, 그 동안 **「새 버전 배포」도 「버전 전환」도 거절됩니다.** 처분하는 길이 둘입니다 — 그
편집을 새 버전으로 **발행**하거나, 편집을 **되돌리기**. 잘커라 콘솔의 「사이트 소스」 화면에서,
또는 사이트에 연결한 AI 에게 말해서 하실 수 있습니다. 사이드바는 그 상태를 미리 보여 주지
않습니다 — 누르셔야 알게 됩니다.

⚠ **AI 확장을 껐다 켜야** 반영됩니다. 켠 직후에 안 보이는 것은 고장이 아닙니다.

⚠ **「내 데이터 보여 주기」는 지금 Claude Code 형식으로만 적어 드립니다**(폴더의 `.mcp.json`).
Codex 로 그 연결을 쓰시려면 손으로 설정하셔야 합니다. 소스를 읽고 고치는 것은 둘 다 됩니다.

## 4. 실제 시나리오

### 시나리오 A — 대행사가 새 판을 보내왔다 (가장 흔합니다)

여러 사이트를 맡고 계시고, 그중 `nasiajai` 의 새 소스 zip 을 받으셨습니다.

```
① 사이드바 → 사이트 전환 → nasiajai
   그 사이트 폴더를 받아 두셨으면 「폴더 열기」를 권해 드립니다. 누르십시오.
   그 폴더가 딛는 버전이 서버와 다르면 두 번호를 함께 보여 드립니다.

② 상태바 왼쪽 아래를 확인            ← nasiajai 인지 눈으로 봅니다

③ 사이드바 → 작업 폴더 → zip 으로 교체 → 받은 zip 고르기
   확인 창이 뜹니다. 세 가지를 보십시오.
     · 출처 표시     — 이 zip 이 어느 사이트 것으로 «표시»돼 있는가
     · 폴더 경로     — 갈아 끼울 자리
     · 그대로 두는 것 — 남는 파일 목록

④ 미리보기 시작 → 화면 확인
⑤ 배포 전 검사
⑥ 새 버전 배포
```

**③의 「출처 표시」가 무엇을 말하나**

| 보이는 것                                             | 뜻                                 | 하실 일                                       |
| ----------------------------------------------------- | ---------------------------------- | --------------------------------------------- |
| 이 사이트에서 내보낸 소스로 **표시되어** 있습니다     | 표시가 이 폴더의 사이트와 같습니다 | 그대로 진행                                   |
| ⚠ **다른 사이트**에서 내보낸 것으로 표시되어 있습니다 | 표시가 다릅니다                    | **멈추고 확인하십시오.** 버튼 문구도 바뀝니다 |
| 출처 표시 **없음** — 도구는 알 수 없습니다            | 표시가 아예 없습니다               | 파일 이름과 보낸 곳으로 직접 확인             |

> **「표시 없음」은 흔하고 정상입니다.** 시작 소스 팩에서 만든 소스에는 표시가 없습니다.
> **없다고 잘못된 zip 이라는 뜻이 아닙니다** —
> 도구가 대신 봐 줄 수 없으니 사람이 본다는 뜻입니다.
>
> 표시는 **선언이지 증명이 아닙니다.** 「일치」가 떠도 그건 「그렇게 적혀 있다」까지입니다.

### 시나리오 B — 사이트 셋을 연달아 갱신한다

zip 을 세 개 받으셨습니다. **한 번에 하나씩** 하십시오 — 시나리오 A 를 사이트마다 반복합니다.

```
사이트 전환 → A  →  zip 으로 교체 → 미리보기 → 검사 → 올리기
사이트 전환 → B  →  zip 으로 교체 → 미리보기 → 검사 → 올리기
사이트 전환 → C  →  zip 으로 교체 → 미리보기 → 검사 → 올리기
```

**미리보기는 한 번에 하나만 돕니다.** 다음 사이트로 넘어가기 전에 중지하지 않으셔도 되지만,
갱신할 때 확장이 알아서 멈춥니다.

**섞이기 쉬운 자리**: zip 파일 이름이 `source.zip`·`site.zip` 처럼 비슷하면 헷갈립니다.
받으실 때 `nasiajai-20260823.zip` 처럼 **사이트 이름과 날짜를 넣어 두시면** 확인 창에서 대조가
쉽습니다. 넘기시는 쪽 명세(`spec/storefront-spec.md` §15)가 그 이름으로 보내라고 요구합니다 —
같은 규약이라 양쪽이 맞물립니다.

### 시나리오 C — 새 사이트를 시작한다

```
① 사이트 선택 → 그 사이트
② 예제 zip 다운로드 — zip 파일 하나가 저장됩니다   (받은 zip 이 이미 있으면 건너뜁니다)
③ zip 으로 시작 → 그 zip 과 **빈 폴더**를 고릅니다 — 있는 파일을 덮지 않습니다
④ 폴더 열기 → 사이트에 연결 → 그 사이트에 붙입니다
⑤ 미리보기 → 배포 전 검사 → 새 버전 배포
```

첫 납품에는 **출처 표시가 없습니다.** 정상입니다 — 아직 어느 사이트에서도 나온 적이 없으니까요.
한 번 올리고 나면 그 뒤로 우리가 내보내는 소스에는 표시가 붙습니다.

### 시나리오 D — 대행사에게 지금 소스를 넘긴다

**zip 으로 내보내기** 를 쓰십시오. 손으로 압축하지 마십시오 — 미리보기 열쇠와 자격증명이
딸려 갑니다. 내보내기는 그것들을 빼고 묶고, **이 폴더가 어느 사이트 것인지 표시를 찍어** 줍니다.
대행사가 그 zip 을 **범용 압축 도구로 풀어** 고친 뒤 다시 묶으면 표시가 따라와 시나리오 A 의
③에서 「일치」로 보입니다. 잘커라 확장으로 풀었거나 처음부터 새로 만들었다면 표시가 없습니다 —
그때는 「표시 없음」이 뜨고, 그게 정상입니다.

### 시나리오 E — 올린 뒤에 잘못된 걸 알았다

```
버전 이력  → 어느 판이 있는지 봅니다
버전 전환  → 어느 판을 켤지 고릅니다(되돌리기도 여기서)
```

올려 둔 판은 남아 있으니 되돌릴 수 있습니다.

### 시나리오 F — 개시한 사이트를 검색에 알린다

사이트가 `robots.txt` 와 `sitemap.xml` 을 내면, 남은 일은 검색 엔진 콘솔 세 곳에 **등록 → 소유 확인 → 사이트맵
제출**을 하는 것입니다. 세 곳의 순서는 같고 소유 확인 방법만 다릅니다. 대표 주소가 정해진 뒤 한 번 하면 되고,
주소를 바꾸면 다시 합니다.

**등록할 주소는 콘솔 「커스텀 도메인」에서 대표로 세운 그 주소**입니다. 플랫폼 주소(`*.zalkera.com`)는 검색
색인을 막아 두었으므로 그 주소를 등록하면 색인되지 않습니다. 아래에서 `$B` 는 그 주소이고 `https://` 까지
포함합니다 — 예: `B="https://www.example.com"`.

먼저 사이트가 무엇을 내는지 보십시오(잘커라 시작 팩에서 만든 사이트는 둘 다 냅니다. 직접 만든 소스라면 여기서
확인하십시오).

```bash
B="https://www.example.com"          # 대표 도메인으로 바꾸십시오
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0 Safari/537.36"
curl -sA "$UA" "$B/robots.txt"
# Disallow: 에 /api 가 있는지 봅니다(쇼핑몰 팩은 장바구니·결제 경로도 함께 막습니다)
curl -sA "$UA" "$B/sitemap.xml" | grep -o '<loc>[^<]*</loc>'
# 홈이 있고(시작 팩이면 /policies 도), 상품·글·카테고리가 있으면 그만큼 늘어납니다. localhost 로 시작하면 대표 도메인부터 확인하십시오
```

맨 `curl` 은 방화벽에 막혀 403 이 날 수 있어 `UA` 를 붙였습니다. 브라우저 주소창에 `$B/robots.txt` 를 넣어 열어도
같은 것을 봅니다. `robots.txt` 앞부분은 Cloudflare 가 붙이는 관리 블록입니다(검색 크롤러 허용 · AI 학습 크롤러
차단). 사이트가 낸 줄은 그 뒤에 옵니다.

| | 등록 | 소유 확인 | 사이트맵 제출 |
| --- | --- | --- | --- |
| **Google Search Console** | 속성 추가 — 「도메인」 유형(www 유무·http/https 를 한 번에 덮습니다) | **DNS TXT 레코드**(이 유형은 DNS 확인만 받습니다) | Sitemaps 메뉴에 `$B/sitemap.xml` |
| **네이버 서치어드바이저** | 웹마스터 도구 → 사이트 등록 — `$B` 그대로 | **HTML 태그** — 잘커라 콘솔 「환경변수」에 확인값 등록(아래) | 요청 → 사이트맵 제출에 `$B/sitemap.xml` |
| **Bing 웹마스터 도구** | Google Search Console 에서 **가져오기** | 가져오기면 생략. 안 쓰면 Bing 이 주는 방식(XML 파일·메타 태그·CNAME) 중 하나 | 가져오기가 사이트맵도 가져옵니다 |

권하는 순서는 **구글 → Bing → 네이버**입니다. 구글을 DNS 로 확인하면 Bing 은 가져오기로 끝나고, 잘커라 콘솔을
만지는 곳은 네이버 하나만 남습니다.

**구글 — DNS 레코드.** Search Console 이 주는 `google-site-verification=…` 값을 도메인의 DNS 에 TXT 레코드로
넣고 반영을 기다린 뒤(`dig +short TXT example.com` 에 보이면) 「확인」을 누르십시오. 소스도 배포도 건드리지
않습니다. DNS 를 만질 수 없다면 속성을 「URL 접두어」 유형으로 따로 만드십시오 — 그 유형만 HTML 파일 확인이
열리고, 대신 www 유무·http/https 를 각각 등록해야 합니다. HTML 파일은 소스의 `public/` 폴더에 넣고 새 판을
올려야 하므로(시나리오 A~C) 손이 더 갑니다.

**네이버 — 환경변수.** 서치어드바이저가 주는 `<meta name="naver-site-verification" content="…">` 의 `content`
값을 잘커라 콘솔 「환경변수」에 이 이름으로 넣으십시오.

```
NEXT_PUBLIC_NAVER_SITE_VERIFICATION = <content 값>
```

저장하면 사이트가 다시 빌드됩니다(업로드 사이트는 저장 알림의 「빌드 기록」으로 진행을 볼 수 있습니다).
끝난 뒤 아래가 한 줄을 내면 서치어드바이저에서 「소유확인」을 누르십시오. 값을 소스에 직접 적지 않습니다 —
소스는 대행사·다른 사이트로 흘러가지만 환경변수는 이 사이트에만 붙습니다.

```bash
curl -sA "$UA" "$B/" | grep -o '<meta name="naver-site-verification"[^>]*>'
# 한 줄. 403 이 아닌데 0 줄이면 재빌드 전이거나 변수 이름 오타입니다
```

그다음 「요청 → 사이트맵 제출」에 `$B/sitemap.xml` 을, 「검증 → robots.txt 검증」에서 검색 크롤러가
허용(`User-agent: *` 아래 `Allow: /`)으로 읽히는지 보십시오.

**Bing — 가져오기.** Bing 웹마스터 도구에서 「Google Search Console 에서 가져오기」를 고르고 구글 계정을 연결하면
확인된 속성과 사이트맵이 함께 넘어옵니다. Bing 색인을 참조하는 AI 검색이 있어 챙겨 둘 만합니다.

**제출 뒤에 볼 것** — Search Console 「Sitemaps」의 「성공」과 발견된 URL 수 · 「URL 검사」에 `$B/` 를 넣어
「색인 생성 요청」 · 서치어드바이저 「요청 → 사이트맵 제출」의 처리 상태 · Bing 「Sitemaps」의 「성공」. 색인 자체는
며칠 걸리므로 콘솔에 「성공」이 떴는데 검색 결과에 아직 없는 것은 정상입니다.

**그 뒤에는** — 상품·글은 `sitemap.xml` 이 한 시간 안에 다시 만들어질 때 실립니다(`src/app/sitemap.ts` 의
`export const revalidate = 3600`). 소스로 만든 페이지는 새 판을 올리면 실립니다. 소스에 손으로 만든
라우트(`/contact` 같은)는 실리지 않으니 그때는 알려 주십시오. 도메인을 바꾸면 세 콘솔 모두 새 주소로 다시
등록하고 소유 확인도 다시 합니다.

**GA4 는 별개입니다.** 애널리틱스는 사이트맵을 받지 않습니다. GA4 관리 → 데이터 스트림 추가로 받은 측정 ID
(`G-…`)를 콘솔 「환경변수」의 `NEXT_PUBLIC_GA4_ID` 에 넣으면 재빌드 뒤 페이지마다 태그가 실립니다.
`G-` 로 시작하는 형식이 아니면(예: `GTM-…` 컨테이너 ID) 아무것도 실리지 않습니다.

```bash
curl -sA "$UA" "$B/" | grep -o 'googletagmanager.com/gtag/js?id=[A-Z0-9-]*'
# 한 줄이면 됩니다
```

| 증상 | 먼저 볼 것 |
| --- | --- |
| curl 이 403 · 「Sorry, you have been blocked」 | UA 없이 친 것입니다. 위 `UA` 를 붙이거나 브라우저로 여십시오 |
| Search Console 이 「소유권을 확인할 수 없음」 | DNS TXT 전파 전입니다. `dig +short TXT example.com` 에 값이 보일 때까지 기다리십시오 |
| 네이버가 메타 태그를 못 찾음 | 위 curl 이 403 이 아닌데 0 줄이면 재빌드 전이거나 변수 이름 오타입니다. 홈에서 확인하면 됩니다 |
| 사이트맵이 「가져올 수 없음」 | `curl -sA "$UA" "$B/sitemap.xml"` 이 200 인지, `<loc>` 이 `localhost` 가 아닌지 보십시오 |
| 플랫폼 주소(`*.zalkera.com`)로 등록했다 | 그 주소는 색인이 막혀 있습니다. 대표 도메인으로 다시 등록하십시오 |
| GA 태그가 안 실린다 | `NEXT_PUBLIC_GA4_ID` 값이 `G-` 로 시작하는지, 저장 뒤 재빌드가 끝났는지 보십시오 |

## 5. 잘 안 될 때

| 증상                                   | 먼저 볼 것                                                        |
| -------------------------------------- | ----------------------------------------------------------------- |
| 버튼이 회색이다                        | 그냥 눌러 보십시오 — 무엇이 필요한지 말해 드립니다                |
| 「이 폴더는 다른 사이트의 소스입니다」 | 상태바의 사이트와 폴더가 어긋났습니다. **이 폴더의 사이트로 돌아가기** 를 누르시면 폴더 쪽으로 맞춥니다 |
| 미리보기가 안 뜬다                     | **진단** 을 누르십시오 — npm·프록시·서버 연결·사이트 소스·의존성 설치를 봅니다. ⚠ 진단이 적는 Node 는 **편집기가 품은 것**이라 늘 ✅ 입니다. 이 컴퓨터에 낡은 Node 가 깔려 막히는 경우는 **진단으로 안 보이니** 터미널에서 `node -v` 로 보십시오 |
| 남이 올린 최신 소스로 내 폴더를 맞추고 싶다 | **서버 판으로 교체**. 「소스 다운로드」는 빈 폴더만 받습니다 |
| 「지난 갈아 끼우기가 끊긴 흔적」이 뜬다 | 그 폴더에 원래 소스가 있습니다. 옮기실 것을 옮기신 뒤 지우시면 알림도 멎습니다 |
| 갱신이 「비어 있지 않습니다」로 막힌다 | 「zip 으로 시작」을 쓰고 계십니다. **zip 으로 교체** 가 맞습니다. 빈 폴더였는데도 막히면 앞서 받다가 중간에 멈춘 파일이 남은 것이니 폴더를 비우고 다시 하십시오 |
| 갈아 끼운 뒤 미리보기가 느리다         | 두 「교체」 다 `node_modules` 를 지우므로 처음 한 번은 다시 받습니다. 정상입니다 |

**진단**(`잘커라: 진단`)이 대부분의 답을 줍니다. 그래도 막히면 출력 패널의 「잘커라」 채널
내용을 함께 보내 주십시오.
