# 결정 기록 — 안 짓기로 한 것과 그 이유

**구현의 정본은 코드다.** 어떻게 도는지는 소스와 KDoc 이 말하고, 무엇이 나갔는지는
`CHANGELOG.md` 와 태그가 말한다. 이 문서가 드는 것은 그 어느 쪽도 안 담는 것 하나다 —
**검토했고 안 짓기로 한 것, 그리고 그 근거.**

⚠ **없으면 돌아온다.** 기각한 안은 시간이 지나면 좋은 아이디어처럼 다시 올라온다. 근거가
사라진 상태에서 재론하면 같은 검토를 처음부터 다시 하게 되고, 이번에는 다르게 결론 나기도 한다.

**새 사실이 있으면 재론해도 된다.** 여기 적힌 것은 「영원히 금지」가 아니라 **「그때 이런 근거로
안 했다」**다. 뒤집으려면 그 근거가 왜 더는 안 서는지를 대면 된다.

---

## CLI 는 `@zalkera/*` 스코프 **밖**에 낸다 — 맨 이름 `zalkera`

**경계**: `@zalkera/*` = 고객 소스가 **`import` 하는 것**(계약) · 맨 `zalkera` = 사람이 터미널에서
**치는 것**(도구).

`@zalkera/client` 는 이 시스템에서 스코프의 뜻을 이미 정해 놨다 — 고객 `package.json` 의
의존으로 선언되고, 서버가 그 **최소 버전을 광고**하며(`precheck`), LLM 이 읽는 규약 정본이
`node_modules/@zalkera/client/llms.txt` 이고, `diagnostics` 가 고객 소스의 호출 이름을 그
패키지의 실제 export 와 대조한다. CLI 는 그중 어느 것도 아니다.

**스코프에 넣으면 생기는 실해**: 우리 나침반이 「고객 LLM + 로컬 코드 유지보수」다. 에이전트가
`node_modules/@zalkera/client` 에서 규약을 읽는 그 환경에서 「zalkera devtools 를 쓰라」는 말을
들으면, 형제 패키지처럼 보이는 이름을 **사이트 프로젝트 안에** 설치할 개연이 크다
(`npm i @zalkera/devtools`). 그러면 CLI 가 사이트 의존 트리에 들어가고 그 `package.json` 이
업로드돼 서버 빌드가 CLI 를 설치한다. 지금 그것을 막는 검사기는 **없다.**
맨 이름은 그 오인을 안 만든다 — `npm i zalkera` 는 「명령을 의존으로 넣는다」로 읽혀 손이 멈춘다.

⚠ **`@zalkera/devtools`·`@zalkera/cli` 를 별칭으로 함께 내지 않는다.** 판을 올릴 때마다 **둘 다**
발행해야 하고(최소판 게이트가 하나라 한쪽만 올라가면 별칭 사용자가 갇힌다), 발행 대상이 둘이면
언젠가 한쪽이 빠진다.

## `@zalkera/devtools-core` 는 발행하지 않는다 — 번들한다

확장이 이미 esbuild `--alias` 로 그렇게 싣고, CLI 도 같은 문을 쓴다. 발행하면 **공개 계약 표면이
하나 더** 생기는데, 이 레포는 `storefront-kit` 을 철회하며 「계약 출처는 `client` 하나」로
좁혀 놨다. core 의 API 는 우리 둘(확장·CLI)만 쓰는 내부 모양이라 계약으로 굳히면 못 고친다.

⚠ 대가: 번들이 자립하는지 **매번 확인해야 한다.** `npm pack` 은 `dist/` 에 있는 것을 묻지 않고
담으므로, `tsc` 조각이 남아 있으면 고객 기계에서 `ERR_MODULE_NOT_FOUND` 다. `pack-cli.mjs` 가
그 자리를 잰다.

## ⛔ 다시 올리지 말 것

### 동시 업로드 — 덮어쓰기 방어

| 안 | 왜 안 하나 |
|---|---|
| 3-way merge · 자동 병합 | git 수준이다. **오너가 정한 범위 한정을 벗어난다** — 이 축은 「최소 방어」다 |
| 파일 잠금 · 리스 · 체크아웃 | 새 상태 기계(회수·만료·강탈)가 통째로 따라온다 |
| 실시간 협업 표시(presence) · 동시 편집 | 같은 이유 |
| 파일 단위 충돌 검출 | 원장의 단위는 **판(zip 전체)**이다. 단위를 쪼개는 것은 원장 모델 변경이다 |
| 확장이 올리기 전에 혼자 판정 | 확장은 **서버 술어를 재현할 수 없다**. 서버 통과 조건에 sha 탈출구가 있는데 `listRevisions` 응답에 `sourceSha256` 이 없어, 번호만 대조하면 **서버가 통과시킬 올리기에 거짓 경고**를 낸다(되돌리기 직후의 정상 흐름). 서버와 확장이 반대로 말하는 것이 진짜 자기모순이다 |
| 서버가 경고만 하고 통과 | 판이 만들어진 **뒤의** 경고는 결정을 바꾸지 못한다 — 같은 유실에 영수증만 붙는다 |
| 이 축을 이유로 git 승격을 앞당기기 | 그 트랙은 자기 근거로 간다 |

### 폴더와 사이트의 소속

| 안 | 왜 안 하나 |
|---|---|
| 멀티루트 워크스페이스(한 창에 사이트 여럿) | 창 단위 자원이 **단수**다 — dev 서버·발급 열쇠·상태바·사이드바·출력 채널. 루트마다 사이트가 다르면 명령마다 「어느 루트냐」 분기가 붙고 그 분기 하나하나가 **교차 오염의 새 표면**이다. `CapturedTenant` 규율도 (사이트, 폴더) 쌍으로 넓어져 캡처 지점 단일화가 무너진다. 잘못 고른 대가가 **교차 테넌트 발행**인 도구에서, 창 하나에 사이트 하나가 곧 보안 경계다 |
| `.vscode/settings.json` 을 소속의 정본으로 | 그 파일은 교차 오염 사고에서 **덮인 바로 그 자리**라, 남은 값이 사고의 결과인지 의도인지 구분할 근거가 파일 안에 없다. 게다가 업로드 zip 이 `.vscode` 를 통째로 빼므로 정본 왕복에서 소실된다 |
| `globalState` 레지스트리를 소속의 정본으로(캐시로는 채택) | 폴더와 함께 **안 움직인다**(경로 변경·다른 기계에서 소실). 사용자에게 안 보여서 어긋났을 때 물어볼 실물이 없다 |
| 디스크 배치 강제(`~/zalkera/<코드>/`) | 레지스트리가 편익을 대체한다. 강제 배치는 기존 폴더 이행 문제·OS별 함정·**소스는 고객 것**이라는 원칙과 충돌한다 |
| 사이트 전환 때 `.env.local` 즉시 청소 | 게이트가 원인을 없애고, 잔존은 유효기간·다음 미리보기 덮어쓰기·로그아웃 제거의 **세 겹**이 거둔다. 제스처 없는 파일 변조를 늘리지 않는다 |
| 활성화 때 자동 복원(표식대로 settings 재작성) | 「도구가 내 설정을 마음대로 바꾼다」가 된다. 복원은 **사람의 제스처로만** 한다 |

### 사이트를 고른 뒤의 흐름

| 안 | 왜 안 하나 |
|---|---|
| 사이드바 항목을 「대상만 바꾸기」와 「소스로 가기」로 쪼개기 | 항목 증식이고, 그 뭉침을 **사용자에게 떠넘기는** 것이다. 진단은 옳으나 해법이 아니다 |
| 평시에도 「새 창/이 창」을 묻기 | 잃을 것이 없을 때 이 창을 덮는 쪽이 옳다 — 폴더는 디스크에 그대로고 레지스트리로 돌아온다. **정말 잃을 것이 있을 때**(미리보기·미저장) 새 창을 기본으로 이미 묻는다. 평시 모달은 백 번의 전환에 백 번의 마찰이다 |
| 사이트 목록 정렬(최근순·로컬본 우선) | 설명 칸이 「지금 작업 중」과 로컬본 경로를 **이미** 말한다. 순서를 바꿔 얻는 것이 없고, 콘솔의 사이트 순서와 편집기가 갈린다. 최근순은 레지스트리에 시각 칸을 더하는 판올림 대비 편익이 없다 — 수십 개면 타자 필터가 그 일을 한다 |
| 최근 사이트 별도 목록·명령 | 고르는 창이 이미 전체 목록이다. 레지스트리는 **캐시이지 UI 자료가 아니다** |
| 입양(표식 없는 폴더가 사이트에 붙는 것)에 사전 확인 | 표식 없는 구판 폴더 **전원**이 물음을 맞는다 — 「표식의 부재로는 막지 않는다」 위반이다. 완화는 되돌리는 단추와 발행 확인 모달(최종 방어선) |
| 로그아웃 때 레지스트리 보존 | 앞 계정의 사이트 코드·경로가 **다음 계정의 제안 표면**에 남는다. 계정 범위 등재의 이유가 그것이다 |
| 폴더 자동 열기(제안 없이) · 미리보기 자동 시작 | 사용자 제스처 없는 창 전환이고, 제스처 없는 자격증명 발급이다 |

### zip 입구

| 안 | 왜 안 하나 |
|---|---|
| 수동 해제 후 「사이트에 연결」로 대체 | OS 해제에는 zip-slip·압축 폭탄·심링크 방어가 없고, `__MACOSX` 가 발행 zip 에 실린다 |
| 콘솔에 올린 뒤 다시 받기로 대체 | **검수 전 소스가 원장에 판으로 남는다.** 미리보기는 정본화 **앞**이어야 한다 |

## 알고 있으면서 안 막은 것

**⑴ 맥 기본 압축이 인코딩 표시를 안 남길 수 있다.** 파인더 「압축」이 UTF-8 이름을 쓰면서 표시를
안 세운다는 보고가 여럿 있다. 그러면 **정상 zip 이 거절된다.** 그래도 표시를 요구하는 쪽을 골랐다 —
거절은 보이고 되돌릴 수 있지만, 표시 없이 받아 주면 CP949 이름이 우연히 유효 UTF-8 인 경우
(「체크.png」→ `üũ.png`) **조용히** 틀린다. 이 박스에서 맥 실물을 만들 수 없어 **확인 못 했다.**

**⑵ NFD 한글 이름은 그대로 풀린다.** 맥은 파일명을 분해형으로 적는다. 그 이름은 표시도 있고 유효
UTF-8 이라 통과하는데, 소스가 조합형으로 그 파일을 가리키면 안 맞는다 — 「이미지가 404 인데 원인이
화면에 없는」 증상이다. **시험이 0건이다.** 푸는 쪽에서 조합형으로 모으는 것이 정석으로 보이나,
파일명을 우리가 바꾸는 것은 그 자체로 판단이 필요하다.

**⑶ 버릴 항목의 이름이 불량하면 zip 전체가 거절된다.** 이름은 계획을 세우기 **전에** 전부 읽으므로
`node_modules` 안의 이름 하나가 불량해도 멈춘다. 안전한 방향이라 그대로 두지만, 사람에게는
「왜 안 쓰는 파일 때문에 막히나」로 보인다.

**⑷ 덮어쓰기 방어는 기반을 아는 문에서만 선다.** 콘솔 zip(포장기가 표식을 빼므로 zip 스스로도
모른다)·연결로만 이은 폴더·구판 확장은 조용히 지난다.

**⑸ 병합은 없다.** 갈라진 뒤 합치는 것은 사람이다 — 받고, 자기 변경을 다시 얹고, 다시 올린다.
둘을 다 담은 판은 그 사람이 올렸을 때 비로소 원장에 생긴다. 같은 사람의 두 기계도 같은 규율이다.

**⑹ 겹친 한 쌍은 선확인이 못 가른다 — 그 창은 밀리초가 아니다.** 판 번호 채번이 대조 트랜잭션
**밖**이라, 같은 번호를 받는 창은 「채번 → 커밋」 사이 **전체**다. 그 사이에 S3 전송과 재파종이
들어가므로 두 업로드의 처리시간이 다르면 **수 초**까지 벌어진다. 마지막 그물은 판 번호의 유일성
제약이라 **유실은 없다** — 다만 받는 문면이 사유를 말해 주지 못한다.

## 열려 있는 쟁점

1. **한 소스 → 여러 사이트 발행**(프랜차이즈·다지점). 재연결과 **다른 동사**로 판정했다 —
   소속의 이동이 아니라 발행 대상의 복수화다. 수요가 실물로 오면 별도 설계로. 소속 모델
   (폴더 하나 = 사이트 하나)을 건드리므로 다른 흐름의 곁가지로 다루면 안 된다.
2. **미승격 레인의 되돌리기와 기반 선언.** 승격 레인은 되돌릴 때 꼬리가 전진해 내용으로
   통과하지만, 미승격 레인은 꼬리가 안 움직여 되돌린 판을 기반으로 선언하면 거절된다.
   대조를 활성 판까지 볼지는 오너 결정.
3. **「알고도 간다」를 원장이 구분할지.** 지금은 무선언 재전송이라 「몰랐다」와 「알고 갔다」가
   같아 보인다. 명시 필드가 그 구분값만큼의 계약 표면을 정당화하는지.
4. **원격(SSH) 창 확인 미이행.** 레지스트리·경로가 같은 확장 호스트에 산다는 전제가 안 잡혔다.
   전제가 틀려도 열기 제안은 실재·소속 확증을 지나므로 실패의 형상이 **교차 열기가 아니라 제안
   누락**이다. 확인: 원격 창에서 받기 → 목록의 설명 칸 → 열기 왕복.
5. **고르는 창의 항목 라벨 소독.** 서버 값이 라벨·설명에 생으로 실리는 기존 자리들(사이트 목록·
   프리셋·버전 목록). 닫을 때 `createQuickPick` 의 간접 대입까지 함께 본다 —
   `scripts/check-notice.mjs` 가 구멍의 위치와 닫는 순서를 적어 뒀다.
   사이트 전환의 판 차이 고지는 이 목록 **밖**이다 — 그 줄에 실리는 번호 둘은 판정 자리
   (`elsewhereOptions`)에서 `plausibleRevisionNo` 로 접혀, 정수가 아니면 값이 아니라 **침묵**이 된다.
