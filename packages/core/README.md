# @zalkera/devtools-core

로컬 레일의 **러너**. 확장도 CLI 도 이 패키지를 부른다 — 어느 길로 오든 동작이 같아야 하므로 로직은
전부 여기 산다.

> **상태: 구현됨 · 미발행.** 14모듈 · 테스트 52. npm 에는 아직 올라가 있지 않다.

## 책임

| | 무엇 |
|---|---|
| 자격증명 | 로그인 결과로 프리뷰 키를 받아 온다 |
| 환경 조립 | `.env.local` 을 만들거나 갱신한다 |
| 의존성 | 개발 서버가 뜰 수 있는 상태로 프로젝트를 만든다 |
| 개발 서버 | 기동·중지·로그 수집·포트 선택 |
| 패킹·발행 | 올릴 수 있는 형태로 묶고 서버에 보낸다 |
| 진단 | 무엇이 없어서 안 되는지 사람 말로 말한다 |

## 못박아 둔 규율

구현이 시작되기 전에 정해 둔 것들이다. 어기면 조용히 남의 데이터를 밟는다.

- **`.env.local` 은 정해진 칸만 갱신하고 나머지는 보존한다.** 사용자가 직접 넣은 값(외부 서비스 키 등)을
  덮어쓰지 않는다.
- **의존성은 매번 새로 받지 않는다.** 잠금 파일 해시 + 플랫폼을 키로 캐시하고, 프로젝트에는 하드링크로
  연결한다. 심볼릭 링크는 번들러가 거부하고, 하드링크는 **같은 파일시스템**에서만 되므로 아니면 복사로
  폴백한다.
- **패킹할 때 `node_modules` 는 반드시 제외한다.** 서버는 그것을 받지 않는다.
- **배포 전 검사는 조언이지 차단이 아니다.** 서버가 받아 줄 것을 이 도구가 먼저 막으면, "소스를 직접
  올리는 길"을 우리 손으로 좁히는 것이 된다.
- **비밀은 파일에 쓰지 않는다.** 로그인 토큰은 호출자(확장)의 안전 저장소에 남고 여기서는 다루지 않는다.
