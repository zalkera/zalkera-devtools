# zalkera — VS Code 확장

터미널 없이 쓰는 길. 잘커라 사이트 소스를 로컬에서 열고, 고친 결과를 **바로 보고**, 올린다.

> **상태: MVP 구현됨 · 미배포.** 마켓플레이스에 없고 VSIX 도 아직 굽지 않았다. 아래 명령은 코드로 존재하나
> **데스크톱 VS Code 에서 한 번도 실행해 보지 않았다** — 그 첫 실행이 다음 할 일이다.

## 왜 확장인가

비개발자에게 "Node 를 까세요"를 요구하면 거기서 끊긴다. VS Code 는 자체 Node 를 이미 싣고 있어서,
확장이 그것으로 개발 서버를 띄우면 **따로 깔 것이 없다.** Cursor·Windsurf 같은 포크에서도 같은 확장이
그대로 먹는다.

## 표면은 넷뿐

사이드바 뷰 1 · 상태바 1칸 · 출력 채널 1 · 명령 팔레트. **웹뷰는 쓰지 않는다** — 화면을 그리기 시작하면
그 화면이 곧 제품이 되고, 확장이 두꺼워져 CLI·데스크톱이 같은 것을 재사용하지 못한다.

```
zalkera.signIn / signOut          로그인·로그아웃(로그아웃은 .env.local 의 키 줄도 지운다)
zalkera.site.create               예제로 시작 — 시작 소스를 받아 새로
zalkera.site.open                 내 사이트 소스 받기 — 이미 있는 사이트를 로컬로
zalkera.site.link                 이 폴더를 내 사이트로 연결
zalkera.preview.start / stop / restart
zalkera.publish                   묶어서 올리기
zalkera.rollback                  이전 버전으로 되돌리기
zalkera.precheck                  배포 전 검사 — **조언이지 차단이 아니다**
zalkera.doctor                    무엇이 없어서 안 되는지 점검

# 아직 없는 것: zalkera.agent.connect(MCP 등록)
```

## 편집은 하지 않는다

코드를 고치는 것은 **당신과 당신의 에이전트**(Claude Code · Codex 등)다. 확장 안에 채팅을 넣지 않는
이유가 그것이다 — 넣는 순간 우리 토큰이 들어가고, "쓰던 AI 구독으로 고친다"가 거짓이 된다.

확장이 하는 일은 넷이다: 런타임 배달 · 자격증명 배달 · MCP 등록 대행 · 프로세스 관리.

## 로그인

브라우저로 왕복하는 표준 OAuth(PKCE)를 쓰고, 복귀는 **루프백 주소**(`http://127.0.0.1:<임시포트>`)로
받는다. 편집기마다 다른 커스텀 URL 스킴에 기대지 않으므로 포크에서도 같은 동작이다.

로그인 토큰은 VS Code **SecretStorage** 에만 둔다 — 워크스페이스 파일에 쓰지 않는다.

## 프리뷰

**실제 브라우저 탭**으로 연다. 확장 안의 웹뷰는 쿠키·보안정책이 실제 탭과 달라서, 하필 "로컬에선 됐는데
배포하니 다르다"를 만드는 자리다.

프리뷰는 **당신의 실제 상용 데이터**를 읽는다. 대신 프리뷰용 자격증명으로는 쓰기가 안 되고, 그 차단은
서버가 집행한다.
