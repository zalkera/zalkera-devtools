# @zalkera/devtools-cli

터미널에서 쓰는 길. VS Code 를 쓰지 않거나, 스크립트·CI 에서 돌릴 때를 위한 것이다.

> **상태: 받기·올리기 축이 선다.** `pull`·`push`·`status`·`baseline` 과 로그인이 돈다.
> 발행·되돌리기·버리기·미리보기는 **아직 없다** — 아래 「아직 없는 것」을 보라. npm 에 올라가 있지 않다.

## 지금 되는 것

```
zalkera login                  # 브라우저로 로그인 (사이트를 안 물어본다)
zalkera pull --site <사이트코드>  # 빈 폴더에 처음 받을 때
zalkera status                 # 이 폴더와 사이트가 어떻게 다른지
zalkera pull                   # 이미 받은 폴더를 지금 판에 맞춘다
zalkera push                   # 이 폴더에서 고친 것을 사이트 쪽에 올린다
zalkera baseline               # 기준 기록만 다시 세운다(파일은 안 건드린다)
zalkera logout
```

`--site` 는 **폴더가 소속을 모를 때만** 필요하다. 한 번 받으면 폴더가 그것을 기억한다.

옵션: `--site <사이트코드>` · `--folder <경로>` · `--revision <판번호>` · `--discard-local` ·
`--overwrite-unseen` · `--verbose`

## 아직 없는 것

`publish` · `rollback` · `discard` · `preview` · 로컬 MCP 서버. 설계는 서 있고
(`backend/doc/design/memos/184-local-source-sync.md`) 트랜치가 T3 부터다.

**올린다고 켜지지 않는다.** `push` 는 사이트 쪽 「편집 중인 것」에 얹을 뿐이고, 손님에게 보이려면
콘솔에서 발행해야 한다. 발행 전에 미리보기로 확인하는 자리도 콘솔이다.

## 받기가 무엇을 하고 무엇을 안 하나

- **서버가 지운 파일은 이 폴더에서도 지운다.** 안 지우면 다음 올리기에서 그 파일이 되살아난다.
- **이 폴더에만 있는 파일은 안 건드린다.** 기준 기록의 판에도 받을 판에도 없던 파일이 그것이다.
- **고쳐 둔 것이 있으면 아무것도 하지 않고 멈춘다.** 진행하려면 `--discard-local` 을 붙이는데,
  그때도 버리지 않고 **옆 폴더**(`../<폴더이름>.zalkera-saved/`)로 옮긴다.
- **파일을 합치지 않는다.** 병합 기계는 짓지 않는다는 것이 설계 결정이다.
- 중간에 끊겨도 **다시 실행하면 이어받는다.** 파일시스템에 트랜잭션이 없으므로 원자성이 아니라
  **멱등 재실행**이 계약이다.

## 올리기가 무엇을 하고 무엇을 안 하나

- **한 번에 보낸다.** 나눠 보내면 사이트 쪽에 의도한 변경의 **반쪽이 걸린 상태**가 생기고, 그 사이
  누가 발행하면 그 반쪽이 판이 된다. 그래서 상한을 넘으면 나누지 않고 **거절**한다 — 그때 길은
  콘솔에서 소스를 통째로 올리는 것이다.
- **사이트 쪽 편집이 건드린 파일 중 그 내용을 이 폴더가 안 들고 있는 것이 있으면 멈춘다.**
  그대로 올리면 그 편집이 사라지는데, 「내가 읽은 값 위에 얹는가」라는 검사는 그것을 **못 막는다**.
  진행하려면 `--overwrite-unseen`.
  - 받기는 **판**을 받지 편집을 받지 않는다. 그래서 남이 콘솔에서 고쳐 둔 파일은 이 도구로는
    내용을 가져올 수 없고, 명시 동의 없이는 못 올린다 — 그 편집을 콘솔에서 먼저 정리해 주세요.
  - 내가 올린 편집은 다음 회차에 안 걸린다(사이트 쪽 내용이 곧 내 폴더의 내용이다).
- **글자로 된 파일만 올린다.** 그림·글꼴·압축 파일이 바뀌었으면 거절한다 — 이 길로 보내면 조용히
  망가지기 때문이다. 그때도 길은 콘솔의 소스 통째 올리기다.
- **응답을 못 받으면 「올라갔는지 모른다」고 말한다.** 「아마 올라갔을 겁니다」라고 말하지 않는다.
  다음에 다시 실행하면 사이트 쪽과 대조해 정리한다.
- **안 올라가는 파일이 두 종류다.**
  - 이 도구가 애초에 안 보는 것 — `.env*`·개인키·`node_modules/`·`.next/`·`dist/`. 목록에도 안 뜨고
    「고친 것」으로도 안 세어진다. 환경변수는 콘솔의 환경변수 화면에서 관리한다.
  - 사이트가 받지 않는다고 답한 것 — 빌드가 만드는 자리 따위. 그것만 **빼고 다시 보내고
    이름을 말한다.**

## 로그인 정보가 어디 있나 — 확장보다 약하다

이 도구는 로그인 정보를 **컴퓨터의 파일에 평문으로** 둔다(`~/.config/zalkera/auth.json`, 권한 0600).
그 컴퓨터를 쓸 수 있는 사람은 이 사이트를 고치고 배포할 수 있다.

VS Code 확장은 OS 키체인을 쓴다 — 그쪽이 **엄밀히 더 강하다.** 여기 담기는 것은 갱신 토큰이라
보관의 반경도 더 넓다. 키링 우선·평문 폴백이 지향점이고, 그 자리는 아직 비어 있다.

요구사항: **Node.js 20+**. (확장으로 쓰면 Node 설치가 필요 없다 — VS Code 가 이미 싣고 있는 것을 쓴다.)

로직은 전부 [`@zalkera/devtools-core`](../core) 에 있다. 이 패키지는 인자 해석과 출력만 맡는다.
